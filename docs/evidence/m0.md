```python
document = Document()
```

## Raster reconstruction proxy

Ghostscript 10.06.0 and Poppler 26.01.0 ran on the same benign PDF.

```sh
gs -q -dSAFER -dBATCH -dNOPAUSE -sDEVICE=pdfimage24 -r144 \
  -sOutputFile=raster-control.pdf control.pdf
pdftotext raster-control.pdf raster-control.txt
pdftoppm -r 144 -singlefile control.pdf source
pdftoppm -r 144 -singlefile raster-control.pdf reconstructed
```

The PDF grew from 3,206 to 7,871 bytes. Poppler recovered only a form feed
from the reconstructed PDF. Both renderings were 1,190 × 1,684 pixels.
The independently rendered PPM files differed in 6,597 color-channel bytes.
This proxy illustrates a tradeoff between visible content and extractable
text. It supplies no OCR result and no claim of visual equivalence.

Dangerzone CLI execution remains outstanding. Initial discovery found no available
Dangerzone CLI or cached image. The proxy does not measure Dangerzone's
isolation, OCR or reconstruction behavior.

disallowed requests. It covers one local scan flow with the routes checked

## DOCX structure versus renderer export

The benign DOCX control from the pinned structural scanner check was
processed with python-docx 1.2.0, LibreOffice 26.2.6.3, and Poppler 26.01.0.
Direct structural inspection returned two runs.

| Run text | Explicit hidden flag | Found in text extracted from renderer export |
| --- | --- | --- |
| Quarterly review | No | Yes |
| Routine editorial note | Yes | No |

LibreOffice exported the document with its default Writer PDF settings.
Poppler returned only the visible body line, followed by a page delimiter.
Both runs were observed in the source package. The difference supports
reporting extraction, renderer export and visibility as separate evidence.
It does not establish behavior across Word versions, alternate rendering
settings, tracked changes, inherited styles or accessibility layers.

To reproduce on the tested Linux environment, generate `control.docx` using
the python-docx example above and create an empty `output` directory beside
it. Run the following from that directory.

```sh
timeout -k 2 18 bwrap --unshare-all --die-with-parent \
  --ro-bind /usr /usr --symlink usr/bin /bin \
  --symlink usr/lib /lib --symlink usr/lib64 /lib64 \
  --dev /dev --proc /proc --tmpfs /tmp \
  --ro-bind /etc/fonts /etc/fonts \
  --ro-bind /etc/libreoffice /etc/libreoffice \
  --ro-bind /etc/ld.so.cache /etc/ld.so.cache \
  --ro-bind "$PWD/control.docx" /input.docx \
  --bind "$PWD/output" /out --clearenv \
  --setenv HOME /tmp --setenv PATH /usr/bin --setenv LANG C.UTF-8 \
  /usr/bin/libreoffice -env:UserInstallation=file:///tmp/lo-profile \
  --headless --convert-to pdf --outdir /out /input.docx
timeout 8 pdftotext output/input.pdf -
```

The first run omitted the distribution's LibreOffice registry mount and
failed before conversion. The successful run included that read-only mount
and used a fresh profile. It had no access to the source directory or host
home. This was a benign control, not a certification of parser isolation.

## Dangerzone document-to-pixels baseline

On 2026-11-23, the public OCI image index
`ghcr.io/freedomofpress/dangerzone/v1@sha256:4a7588f245cbdc6f78970f6491a7af964d5cf6dc9eca5c75c2d0904fa52269ac`
verified with Cosign using the public key from Dangerzone source revision
`f97310cad237d2f96a58df3ab004c241628a39dd`. The AMD64 child digest was
`sha256:daf0058249eaa679584b3e053a223d6411c9d0bf256a8d840ae23892cd08745b`.
Its compressed layer was 489,676,500 bytes.

Podman ran the signed image's first conversion stage with its default entry
point, the upstream seccomp profile from the same source revision, no
network, one CPU, 1,200 MiB memory, at most 128 processes and a 32-second
timeout. The only document inputs were the two benign controls described above.
The converter reported success for both. Each output matched the framing in
the upstream reader: three big-endian two-byte integers for page count,
width and height followed by exactly three bytes per pixel.

| Input | Pages | Dimensions | Bytes | SHA-256 |
| --- | --- | --- | --- | --- |
| PDF | 1 | 1,240 × 1,755 | 6,528,606 | `1745f4d7a66b2ab59895457568220ac46bc2db7883c1de950d155081b0da2db5` |
| DOCX | 1 | 1,275 × 1,650 | 6,311,256 | `d4a31d9f3443e6239f2126f44702d6c7584515fecc6ae05c0cfd6579ffe96d2e` |

For reproduction, fetch `share/freedomofpress-dangerzone.pub` and
`share/seccomp.gvisor.json` from the pinned source revision. Verify the
index digest with `cosign verify --key` using the public key, then pull
the listed AMD64 digest. With the seccomp profile saved as `seccomp.json`,
run the following for each control, changing the input and output paths.

```sh
timeout -k 3 32 podman run --pull=never --rm --log-driver=none \
  --security-opt no-new-privileges --userns nomap \
  --security-opt "seccomp=$PWD/seccomp.json" \
  --cap-drop all --cap-add SYS_CHROOT \
  --security-opt label=type:container_engine_t \
  --network none --user dangerzone --cpus 1 --memory 1200m \
  --pids-limit 128 --env RUNSC_FLAGS=--ignore-cgroups -i \
  ghcr.io/freedomofpress/dangerzone/v1@sha256:daf0058249eaa679584b3e053a223d6411c9d0bf256a8d840ae23892cd08745b \
  /usr/bin/python3 -m dangerzone.conversion.doc_to_pixels \
  < control.pdf > pdf.rgb
```

This measures the document-to-pixels stage and its output framing on two
input files. The application CLI, final PDF generation, OCR, preservation
and performance comparisons remain outstanding. The listed SHA-256 values
identify outputs from these runs. Regenerated fixtures and different fonts
or platform versions may change output bytes.


generated PDF as per-run evidence.
